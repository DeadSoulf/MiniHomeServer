# Обнаружение устройств локальной сети и Zigbee

Версия **0.3.0**. Новые функции доступны в интерфейсе: **«Устройства сети»**.

## Что обнаруживается в локальной сети

MiniHomeServer запускает поиск **с самого Debian-сервера**, а не с браузера или ноутбука. Используются:

- Таблица IPv4-соседей (ARP через `ip -j -4 neigh show`).
- Небольшая проверка доступности каждого адреса напрямую подключённой частной подсети (одно TCP-соединение на порт 80 без передачи данных), которая помогает обновить ARP.
- UPnP/SSDP и mDNS (если устройства отвечают), чтобы получить подсказку об имени или типе.

Сканируются только напрямую подключённые частные подсети IPv4 с префиксом **/24–/30** (до 254 адресов каждая, максимум две), например `10.10.10.0/24`. Запрещены сканирование чужих публичных IP, диапазоны для VPN, проверка паролей и управляющие запросы. Первое сканирование запускается при открытии страницы, затем повторяется не чаще одного раза в 10 минут при открытой странице; вручную — кнопкой **«Сканировать сеть»** с защитой от частого повторения.

Отображаются IP, MAC (если известен), имя из mDNS, сетевые подсказки о типе устройства, время последнего обнаружения и состояние на момент последнего сканирования.

**Ограничения:** обнаружение не гарантирует 100% устройств. Гостевые VLAN, другие маршрутизируемые подсети, выключенные/спящие устройства и оборудования, не отвечающие на ARP/mDNS/SSDP, могут отсутствовать или показываться как неактивные. Если MAC-адрес неизвестен, идентификатор привязывается к IP, а после обнаружения MAC может измениться.

## Zigbee и шлюзы

**Zigbee-датчики не имеют собственного IPv4-адреса.** Поэтому сканирование LAN покажет шлюз, но не обязательно устройства за ним.

В версии 0.3.0 добавлен первый поддерживаемый способ — **Zigbee2MQTT через MQTT**. По документации Zigbee2MQTT перечень подключённых устройств публикуется как retained JSON в `zigbee2mqtt/bridge/devices`; статусы доступны в `zigbee2mqtt/ИМЯ/availability`, если на шлюзе включена функция availability. <https://www.zigbee2mqtt.io/guide/usage/mqtt_topics_and_messages.html>

### Подключение Zigbee2MQTT

1. В панели открыть **Устройства сети → Подключить шлюз Zigbee2MQTT**.
2. Указать IPv4-адрес MQTT-брокера в непосредственно подключённой сети Debian, обычно порт `1883`.
3. Указать базовый топик `zigbee2mqtt` или свой, если он отличается.
4. При необходимости ввести MQTT-логин и пароль.
5. Нажать **«Сохранить и найти устройства»**. Прочитанные устройства появятся ниже с именем, IEEE-адресом, моделью, производителем и состоянием, если оно опубликовано.

Пароль хранится **только на Debian**, в `/var/lib/minihome/zigbee-gateway.json` с правами `0600`. В API он обратно не выдаётся, показывается только факт его наличия. Запись команд MQTT `/set`, сопряжение устройств, управление реле и нагревателями **не используются**. Приложение делает только MQTT CONNECT и SUBSCRIBE.

Если Zigbee2MQTT availability выключена, показывается «Нет данных», а не вымышленный «Онлайн».

### Другие шлюзы

ZHA в Home Assistant, Tuya, Aqara, Philips Hue, eWeLink/Sonoff, Xiaomi и другие шлюзы **не обязаны** поддерживать MQTT API Zigbee2MQTT. Для них нужен отдельный адаптер по конкретной модели и протоколу. Присылай **марку и модель шлюза** — тогда добавим соответствующую интеграцию.

Сетевые и Zigbee-объекты можно вручную добавить маркерами на карту; это не включает автоматическое управление. Связь «маркер → реальная интеграция и телеметрия» — следующий этап.

## Настройка и обновление

Работаем строго через [GitHub MiniHomeServer](https://github.com/DeadSoulf/MiniHomeServer) в ветке `main`. Для существующей systemd-установки новой версии можно использовать уже настроенную кнопку **Настройки → Обновления → Проверить GitHub → Установить обновление**. Миграция базы носит аддитивный характер, старые объекты и карта не удаляются.

Если обновление ещё не настроено, см. [UPDATES.md](UPDATES.md). Исходники не нужно собирать на личном ноутбуке.

## Безопасность сети

Мини-панель может работать на `0.0.0.0:8080`, но HTTP без шифрования не подходит для передачи административного и MQTT-пароля через интернет. Для удалённого доступа используйте HTTPS либо VPN. Используйте отдельные MQTT-учётные данные только на чтение, если брокер поддерживает ACL, и не открывайте порт MQTT во внешний интернет.

### Функциональные ограничения v0.3.0

- Не заменяет полноценный реестр маршрутизатора/DHCP и не может гарантировать все подключённые устройства без доступа к его таблице клиентов.
- Встроенный MQTT-адаптер работает с MQTT 3.1.1 по TCP внутри приватной сети, без TLS.
- Веб-панель показывает реальный список устройств, но ещё не управляет ими и не получает полную телеметрию Zigbee.

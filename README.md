# MiniHomeServer

Веб-панель управления домом и территорией, развёртываемая на собственном Debian-сервере.

## Цель

Единый интерфейс с интерактивным планом участка и дома: объекты, зоны, датчики, исполнительные устройства, камеры, сценарии, события и мониторинг. Карта территории будет добавлена владельцем позднее — до этого интерфейс должен показывать корректное пустое состояние, не выдумывая оборудование и показания.

## Основные принципы

- **Сервер — Debian**, развёртывание через Docker Compose с проверкой существующих служб перед установкой.
- **Код — в этом репозитории**, рабочая ветка — `main`; изменения документировать.
- **Полностью локальное управление**: интерфейс работает без внешних облаков, внешние интеграции опциональны.
- **Модульная архитектура**: веб-панель, API, адаптеры устройств, автоматизации, журнал событий.
- **Безопасность**: обязательная авторизация, роли, журнал команд, запрет публикации паролей/токенов и прямого открытого доступа к исполнительным API.
- **Никаких фиктивных показаний** в рабочем интерфейсе. Неизвестное состояние отображать как «Нет данных».
- **Связь с другими проектами только через интерфейсы** (MQTT/API), без копирования их исходников и смешивания прошивок.

## Концепция интерфейса

1. **Территория:** масштабируемая интерактивная схема участка; слои устройств, камер, датчиков, освещения, охраны, инженерных систем.
2. **Дом:** комнаты, этажи, оборудование и климат.
3. **Котельная:** отопление, температуры, контуры, предупреждения. Подключение к отдельному проекту панели котельной — только через адаптер.
4. **Видео:** интеграция Frigate / RTSP через серверный шлюз, без передачи секретов видеопотоков в браузер.
5. **Автоматизация:** сценарии, расписания, зависимости, история срабатываний.
6. **Настройки:** пользователи и роли, подключения, устройства, назначение объектов на карте, архив, резервные копии.

## Предлагаемая архитектура

- Frontend: React + TypeScript; адаптивный интерфейс/PWA, SVG-план территории с режимом редактирования.
- Backend: Python FastAPI; REST/WebSocket, авторизация и разграничение доступа.
- Хранилище на первом этапе: SQLite на постоянном томе; без лишней инфраструктуры.
- MQTT: Mosquitto (использовать уже существующий экземпляр, если он есть).
- Интеграции: Home Assistant, Frigate, ESP32/ESPHome, Zigbee2MQTT, Modbus/RS-485 — включаются по необходимости.
- Reverse proxy / HTTPS: существующий, если установлен; не дублировать сервисы.

Архитектура предварительная, окончательные сервисы и порты определяются **после аудита Debian-сервера**.

## Порядок работы

1. Провести **только читающий аудит** Debian: версия, архитектура CPU, память, диск, Docker, сетевые службы и уже работающие компоненты умного дома.
2. Согласовать безопасную схему доступа и сохранить резервные копии затрагиваемых конфигураций.
3. Разработать базовый интерфейс и API с аутентификацией, без фиктивных устройств.
4. Импортировать предоставленный план территории, реализовать редактор привязки зон/устройств.
5. Подключать реальные интеграции по одной; проверить статусы, роли и безопасные команды.
6. Добавить автоматизацию, историю событий, мониторинг, обновление и восстановление.

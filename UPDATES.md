# Обновления MiniHomeServer через веб-панель

## Включение на существующем Debian

Для ранее установленной systemd-версии один раз выполните под root на самом Debian:

~~~bash
cd /root/MiniHomeServer
git pull --ff-only
bash scripts/enable-web-updates.sh
~~~

Скрипт проверяет источник репозитория, сохраняет резервную копию приложения, обновляет код и включает системные службы **minihome-update.path** и **minihome-update.service**. Карта, SQLite, настройки и пароль администратора не перезаписываются.

На новых установках через **scripts/install-systemd.sh** функция включается автоматически.

## Использование в браузере

Откройте **Настройки → Обновления MiniHomeServer**, нажмите **Проверить GitHub**, затем **Установить обновление** и подтвердите. Показываются установленные и новые SHA-коммиты, ход работы и результат. Переход на новую версию сопровождается коротким перезапуском панели. Сессия пользователя хранится в SQLite и переживает этот перезапуск.

Обновления исключительно **ручные**: никаких автоматических установок без кнопки.

## Как это работает

- Веб-приложение работает от пользователя minihome без привилегий root.
- Авторизованный запрос с CSRF-токеном создаёт заявку в JSON с проверенным 40-символьным SHA.
- Независимая системная служба под root клонирует **только** https://github.com/DeadSoulf/MiniHomeServer.git (ветка main).
- Служба проверяет совпадение указанного SHA с актуальным HEAD main, синтаксис Python и контрольные суммы установленного кода. Незнакомые локальные правки не перезаписываются.
- Перед установкой создаётся резервная копия кода и снимок базы данных.
- После установки проверяется HTTP health endpoint. Если новая версия не запустится, обновитель восстановит предыдущий код.
- Изменяются лишь файлы веб-приложения и обновителя, но не пароль, карта, конфигурация сети или другие службы.

Данные в каталоге /var/lib/minihome сохраняются. Резервные копии — в /opt/minihome-backups; хранятся последние три успешных набора.

## Диагностика

~~~bash
systemctl status minihome minihome-update.path --no-pager
journalctl -u minihome-update.service -n 80 --no-pager
curl -fsS http://127.0.0.1:8080/api/health
~~~

## Ограничения

Веб-установка обновлений реализована для **systemd**, не Docker Compose. При Docker панель покажет, что служба обновлений не настроена.

Обновитель распространяет только заранее известные файлы приложения. Для новых системных зависимостей или несовместимых миграций базы требуется отдельный план установки.

**Безопасность:** веб-панель на http://IP:8080 использует незашифрованный HTTP, который не защищает пароль. Для доступа из интернета необходим HTTPS или VPN. Открывать дополнительные порты для получения обновлений не требуется.

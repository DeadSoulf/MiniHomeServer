# История изменений

## 2026-11-08 — v0.3.9: калибровка плана в метрах

- Добавлен защищённый API для сохранения размеров изображения территории (ширина и высота в метрах) и сброса калибровки.
- Сохраняет масштаб в существующей таблице settings, без изменения структуры SQLite и координат объектов.
- Размеры контуров строений допускают дробные проценты (с проверкой диапазона и конечности чисел), чтобы при переводе из метров не терять точность.
- Ранее добавленные строения остаются на прежних координатах. Реальные размеры не предполагаются автоматически.


## 2026-11-08 — v0.3.8: интерактивное перемещение, масштабирование и строения

- Добавлено перемещение плана мышью и пальцем, плавное масштабирование колесом, жестом двумя пальцами и кнопками ±; кнопка «Сброс» возвращает исходное положение и 100%. Все слои карты (план, камеры, объекты и строения) увеличиваются и перемещаются вместе.
- Можно добавить «Строение» — прямоугольный контур с шириной, длиной и поворотом; он остаётся интерактивным и перемещается в режиме редактирования. Дом или котельную можно переключить из значка в контур в карточке объекта.
- Для сохранения используется 4 новых столбца SQLite с безопасными значениями по умолчанию. Существующие дома, камеры, настройки и карта не пересоздаются и не меняют координат. Размеры условные, в процентах плана до указания физического масштаба.
- Клик по карте учитывает масштаб и перемещение; перетаскивание карты не создаёт объект случайно. Реальных команд оборудованию и видеопотоков не добавлено.
- Для обновления используется только GitHub main; установка на Debian остаётся ручной.


## 2026-11-08 — v0.3.7: камеры и наглядные версии обновлений

- Камеры можно добавлять отдельной кнопкой на плане. Для камеры задаются угол обзора, направление и условная длина сектора; прозрачный сектор отображается поверх карты и перемещается вместе с камерой.
- Новые параметры сохраняются в SQLite без удаления старых объектов, карты и конфигурации. Данные камер проходят серверную проверку. Видео и управление реальными камерами не добавляются.
- При входе в настройки панель автоматически проверяет наличие новой версии (не чаще раза в 10 минут); установка остаётся только ручной.
- В разделе «Настройки → Обновления» отображается связка версии и SHA: `v0.3.6 · ab8987d896b7` (пример). Версия на GitHub определяется по исходнику `server.py` конкретного коммита, а не по сообщению коммита или состоянию ветки после проверки.
- Проверка через GitHub Actions включает регрессионные тесты API, миграции базы и геометрии секторов. Остаётся только `main`; обновление через веб — вручную.


## 2026-11-08 — v0.3.6: контрольный выпуск веб-обновлений

- Незначительное контрольное обновление без изменений схемы SQLite, системных зависимостей, сетевых настроек и прошивок устройств.
- Версия API изменена с 0.3.5 на 0.3.6. В разделе «Настройки → Сервер» появилась заметная отметка тестового выпуска.
- Выпуск нужен для проверки ручной установки из веб-API MiniHomeServer, скачивания из GitHub main, перезапуска службы, резервного копирования и сохранения карты/SQLite.
- Ветка одна — main. Секреты и реальные адреса инфраструктуры в репозиторий не добавляются.


## 2026-11-08 — предотвращение root-owned SQLite WAL/SHM после обновлений

- На Debian восстановлен MiniHomeServer 0.3.3 после обнаружения файлов minihome.db-wal и minihome.db-shm, принадлежащих root при режиме 0600.
- Причина повторения: чтение SQLite для резервной копии привилегированным обновителем может создавать root-owned служебные файлы.
- Обновитель теперь после резервного копирования проверяет и возвращает владельца **только** SQLite WAL и SHM файлам, затем повторяет проверку доступности базы для пользователя minihome до установки нового кода.
- Системному сервису обновления добавлено CAP_CHOWN, при сохранении ограниченного набора путей ReadWritePaths и прочих ограничений.
- База SQLite, карта, пароль, SSH, настройки сети и работающая версия панели не пересоздаются и не заменяются автоматически.


## 2026-11-08 — аварийное восстановление веб-панели

- Добавлен scripts/recover-web.sh для существующей systemd-установки MiniHomeServer.
- Сначала проверяется локальный HTTP API; работающая служба не перезапускается.
- При недоступности API перезапускается только minihome.service и выводится локальный журнал.
- При подтверждённой ошибке прав SQLite создаётся согласованная резервная копия базы; затем исправляются права только каталога MiniHomeServer и его SQLite-файлов.
- Карта, пароль, сетевые настройки, SSH и другие службы не изменяются; при иной ошибке скрипт останавливается без автоматического исправления.


## 2026-11-08 — v0.3.5: разбор ARP при поиске оборудования

- Устранено падение `unhashable type: list` на массиве `state` в JSON iproute2; сохранена совместимость со строкой и фильтрация FAILED/INCOMPLETE/NONE.
- Добавлены регрессионные проверки настоящего JSON-парсера, форматов состояния, MAC, интерфейса и границ подсети; CI включает новый тест.
- Исправления AF_NETLINK 0.3.4 и SQLite 0.3.3 сохранены. Обновлены NETWORK.md и версия панели; карта, настройки и база не изменяются.
- Проверки выполняются в облаке и CI, без ноутбука; реальная LAN требует проверки после установки.


## 2026-11-08 — v0.3.4: исправление ошибки поиска сети

- Исправлена ошибка «Не удалось получить сетевые параметры Debian» при поиске устройств: `iproute2` использует сокеты AF_NETLINK, запрещённые предыдущим профилем systemd MiniHomeServer.
- Добавлены резервные способы чтения адресов и масок интерфейсов через Linux SIOCGIFADDR/SIOCGIFNETMASK и соседей через `/proc/net/arp`, не требующие AF_NETLINK или прав на изменение сети.
- При новой установке systemd разрешается AF_NETLINK; однократный установщик добавляет узкий drop-in для существующих служб.
- Результаты по-прежнему ограничены напрямую подключёнными частными IPv4-подсетями. Настройки сети, пароль, база данных и карта не изменяются.
- Выпуск публикуется только в `main`; реальное обнаружение на Debian ещё не подтверждено.


## 2026-11-07 — v0.3.3: устранение ошибки SQLite read-only при обновлении

- Причина падения новой версии установлена по журналу Debian: `sqlite3.OperationalError: attempt to write a readonly database` при создании новых таблиц.
- Перед миграцией создаётся согласованная SQLite-резервная копия в закрытом каталоге резервных копий.
- Однократный установщик проверяет стандартные пути без символических ссылок, исправляет владельца и права **только** каталога MiniHomeServer и файлов SQLite (`minihome.db`, WAL/SHM), проверяет запись от пользователя `minihome`.
- Для systemd включено `StateDirectory=minihome` и `StateDirectoryMode=0700`, чтобы права сохранялись после перезапусков.
- Фоновый веб-обновитель проверяет доступность SQLite перед установкой и отказывается обновлять код, если права снова нарушены.
- Пароль, карта, данные SQLite, настройки сети и чужие службы не удаляются.
- Публикация в `main`; фактический запуск на Debian требует применения обновлённого установщика.

## 2026-11-07 — v0.1.0 (первый рабочий MVP)

- Создан сервер на Python (без внешних Python-зависимостей): HTTP API, вход администратора, CSRF-защита, временные сессии и ограничение попыток входа.
- Добавлена база SQLite для объектов, координат, настроек карты и реальных событий конфигурации.
- Добавлена русскоязычная адаптивная веб-панель: «Территория», «Оборудование», «События», «Настройки».
- Добавлен редактор карты: загрузка PNG/JPEG/WebP, создание объектов, выбор точки размещения и перенос значков.

- Добавлены Dockerfile, Compose с привязкой к localhost, пример безопасной конфигурации и инструкция по установке на Debian.
- Добавлены интеграционные API-тесты и проверка через GitHub Actions.
- **Установка на реальный Debian пока не производилась:** доступ Termalin нестабилен.

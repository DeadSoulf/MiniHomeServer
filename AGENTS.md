# AGENTS.md — правила для AI-агентов MiniHomeServer

## Контекст

Разрабатываем автономную веб-панель для управления территорией и домом на Debian.
Пользователь позже предоставит план участка. Никаких координат, устройств и показаний нельзя выдумывать.
`MiniHomeServer` — отдельный репозиторий; сторонние проекты, например контроллеры котельной, интегрируются по стандартным API/MQTT, но не смешиваются с его кодом.

## Главные правила

1. Работать с исходниками в `DeadSoulf/MiniHomeServer` на ветке `main`; **не создавать отдельные ветки без запроса владельца**.
2. Не использовать ресурсы личного ноутбука владельца для сборки, тестов или установки.
3. Не включать в Git пароли SSH, API-токены, приватные ключи, файлы `.env`, реальные адреса инфраструктуры или персональные данные.
4. Прежде чем менять сервер: сделать read-only аудит служб, портов, контейнеров и диска; выяснить, есть ли работающий Home Assistant, MQTT, Frigate, прокси или БД. Не дублировать существующие сервисы.
5. Перед рискованными изменениями делать проверяемую резервную копию; не удалять чужие сервисы и данные.
6. Все команды управления физическими исполнительными устройствами должны требовать авторизацию, проверку роли, ограничения, защиту от повторных команд и журнал аудита. Для критичных действий — подтверждение человеком.
7. Не делать облако обязательным: основной функционал работает в локальной сети.
8. Реальные показания и статусы только из интеграций. При разрыве связи статус «Нет данных/Офлайн», никогда не подставлять демо-цифры.
9. После каждого изменения обновлять документацию и раздел «Изменения» в README или отдельном CHANGELOG.md с датой и эффектом.
10. Перед установкой на сервер проверить конфигурацию, безопасность доступа, совместимость и план отката.

## Модули

- `territory`: карта участка, зоны, слои, перемещение объектов, координаты и масштаб;
- `house`: здания, этажи, помещения и оборудование;
- `devices`: реестр устройств и назначение их функций;
- `integrations`: адаптеры MQTT, Home Assistant, Frigate, Zigbee/ESP32/Modbus;
- `events`: телеметрия, история, тревоги, аудит;
- `automation`: сценарии и безопасные правила;
- `auth`: роли, пользователи, сессии, безопасность;
- `ops`: резервные копии, обновление, диагностика.

## Роли агентов

- **Архитектор:** следит за модульностью, контрактами API, схемой данных.
- **Frontend/UI:** проектирует панель, SVG-карту, мобильную адаптацию и доступность.
- **Интеграции/IoT:** делает адаптеры и обработку недоступных устройств.
- **DevOps:** проводит аудит Debian, готовит Compose, мониторинг, резервное копирование и откат.
- **Security/QA:** тестирует границы доступа, ввод, API, опасные команды, журнал аудита.
- **Документатор:** обновляет README, примеры конфигурации и журнал изменений.

## Минимальные критерии готовности

- Нет публикации секретов и прямых управляющих API в интернете.
- Панель не показывает фиктивные температуры, статусы или видео.
- Утеря связи не приводит к повторному бесконтрольному выполнению команд.
- Есть инструкция по установке и откату, конфигурация вне Git, тесты ключевых API.
- Отдельные адаптеры можно обновлять без переписывания веб-панели.
